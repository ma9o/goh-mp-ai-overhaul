# Early grenade detection and sprint escape in the updated game

Steam app 400750 installed build **26734796**. The infantry throw path exposes a live grenade, its fuse and its initial motion before first contact. A host can use those inputs to choose an explicit escape point outside the predicted danger zone. Two limits matter for the design. The chassis can legitimately resolve a fast request to walk. Native Move and grenade-order execution can advance the selected engine RNG, including when the selected stream is `synced_global`. The complete native escape therefore has no unconditional zero-draw contract.

This pass fills the clamp and applied-speed blanks in I-STANCE, I-MOVE-SPEED and O-MOVEMENT-CHANGE, the airborne-input blanks in I-GRENADE-SCANNER, I-GRENADE-ACTIVE and I-SUBJECT-POSITION, and the output blanks in O-HAZARD-BUILD, O-BURN-MOVE and the three saved-order rows. RVAs below refer to the game. Paired RVAs are **25492057 → 26734796**, offsets are hexadecimal and virtual slots are decimal. ## Detecting a grenade before contact

**Earliest reviewed producer.** On the successful infantry throw path, `0x81D39A..0x81D46D → 0x8320EA..0x8321BD`, the engine records the source, writes the entity origin, arms the fuse, activates the simulator, sets zero linear damping, installs linear and angular velocity, then sets acceleration. Immediately after the last call (`0x8321C2` on the update) these inputs coexist. A host-side design can record the entity identity here and resolve it at the next admitted serial actor update. A spatial query can also discover already-flying entities from other producers. First observation depends on update ordering, registration and the lifetime of the entity. Save an identity across phases and revalidate liveness, extender, active simulator and fuse on each read. [Entity identity and lifetime](entity-id-map-25492057.md)

**Why stock AI often waits.** `0x907760 → 0x91FFA0` walks four sensor vectors at `actor+0xDD0 → sensor+[0x268,0x270)+0x18*i` and reads `subject+0x20`. Its grenade branch requires category 3, visibility (subject flags `+0x10` bit 29) or strictly inside `bomb/detect_grenades × L`, entity `+0x1C0` bit 28 clear, RTTI-compatible `Entity::eStuffExtender` at `entity+0x578 → aggregate+0x20`, item pointer `ext+0x88`, and nonzero dword `ext+0x90`. It scans the item definition (`item+0x40`) tag range `[+0x11E0,+0x11E8)` at stride `0x60` for `grenade`. The standalone classifier `0x907FA0 → 0x9207E0` recognizes the armed tagged item without the category or speed test.

**Prediction contract.** For a free dry segment with zero damping and constant downward acceleration, sample centre and velocity together. Above flat height h, the descending crossing has `t = (vz + sqrt(vz² + 2G(z0 − h))) / G` and `Pxy = (x0,y0) + t(vx,vy)`. On terrain, bracket the first descending crossing of `z(t) − h(x(t),y(t))` within the remaining fuse horizon. Height sampling is `0xA3E8D0 → 0xA5D440(terrain, &xy, level=0)`, returning float in XMM0. At current call site `0xA614E1` RCX is the height interface from the scene object's `+0x18`. With velocity and acceleration in native engine units, compare t directly with the remaining simulation-counter interval. Converting that interval to seconds for display also requires converting v and G before using it in this equation. If expiry comes first, use the airborne XY at expiry. Once contact intervenes, update from observed state. Roofs, walls, water, body extent, the quant integrator and rebound all affect the eventual explosion point. Native tick `0x7310C0 → 0x7442F0` advances the body and checks collision, and contact `0x730D90 → 0x743FC0` changes velocity. An analytic terrain crossing is an estimate of first ground contact. Computing exact final rest would require those scene contacts. Running the live simulator ahead would itself change state. ## Host-only escape to explicit XY

**Admission.** For an MP-only reaction require a matching PE digest, `!remote()` (`0xC0B630 → 0xC2B7A0`), positive native emission role (`0xC0B5D0 → 0xC2B740`), a bound authoritative foot actor and concrete `Actor::eHumanBrain` at `actor+0xDC8` (primary vtable `0x10EC7C8 → 0x110FF88`). A false remote result alone also admits offline contexts. Use the serial actor update after the quant workers join and sensor commit (`0x7EFE5B → 0x804C0B`), with the worker guard `0xA6740 → 0xA7A80`. The brain dispatch `0x9035C0 → 0x91BE00` can skip human slot 35 (`0x941D00 → 0x95A680`) when reconsideration is not due. A per-quant check belongs at the admitted post-commit actor phase. Revalidate `brain+0x39C & 0x3F == 0`, `chassis+0x18 == 0` and `weaponry+0x70` bit 1 clear. Honor player hold/control and active-order bit 28, using the root emergency priority only for a live hazard. Keep clients and quant workers passive. [Multiplayer constraints](../../AGENTS.md)

**Choosing the endpoint.** Let S be the soldier XY and P the predicted detonation or landing XY. For a fresh hostile observation H, form unit vectors g along S−P and e along S−H. Subject `+0x28..+0x30` supplies the last-known position and `+0x64` its update time. Honor position validity and diplomacy before using it. A deterministic policy choice is `u = normalize(g+e)`, which has a positive dot product with both directions when they are defined and not opposite. With only g, use g. With exactly opposed directions, moving strictly away from both is impossible. Give the imminent grenade priority. When S=P, use e if available, otherwise a fixed ordered set of map directions. Resolve near-cancellation and ties consistently.

Use the configured danger radius plus a positive margin R. For a soldier inside R, let `q=S−P`. The outward ray intersects the circle at `s=−dot(q,u)+sqrt(dot(q,u)²+R²−dot(q,q))`. Choose the endpoint slightly beyond this distance and check its actual XY against the radius. Skip an already-safe actor when escape is unnecessary. Evaluate candidate directions in fixed order if terrain blocks the best one. Check the native route's endpoint and initial progress away from danger. A valid endpoint alone cannot establish a safe path or timely arrival. Vanilla `0x8FE840 → 0x917050` constructs `eAreaOutside` centred on the grenade's **current** XY with radius **current 3D separation + 2 engine coordinates**, then calls `0x8C8F60 → 0x8DE560`.

## RNG, resources and validation

The proposed detection reads, flight arithmetic and deterministic endpoint ranking require **zero engine RNG calls**. Native execution has explicit draws. With traversal-flags bit 0 clear, a reachable Move progress branch calls a route probe at `0x8F4621 → 0x90BD73`. Inside it `0x8AE8EA → 0x8C3ECA` obtains the selected RNG, `0x8AE8F9 → 0x8C3ED9` increments its counter and the surrounding instructions update its LCG state. A route-line sampling path also draws at `0x8ACBC0 → 0x8C21B0`. The native grenade planner draws when scheduling the 0.5–1.5 expiry delay at `0x8FDFAE → 0x9167BE`. The relevant serial actor dispatch itself selects the stream. When entity `+0x3A` bit 0 is clear, `0xA1C527 → 0xA3AE77` obtains `synced_global`, installs it at `0xA1C52F → 0xA3AE7F` and calls entity slot 23 at `0xA1C54B → 0xA3AE9B`. A set bit chooses the entity-local stream. The general context push also selects the registered global stream at `0x65F241 → 0x66F2F1`. The getter alone is not a draw. A changed route or a new native order can change the draw schedule relative to vanilla. Thus a literal requirement of zero synced draws **including all native execution** remains unsatisfied.
