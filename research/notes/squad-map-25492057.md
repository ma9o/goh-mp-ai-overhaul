## Commander, display actor and membership

`92F5E0 / 7B6B90` elects the commander from the **first12 eligible members**.
It excludes inactive/pending-deletion entity flags38 bits9/11, nonoperatable
actors, vitality174 low-two-bit states and placer kind2. It computes a 3D
centroid of that accepted subset. At least two vehicle-role actors produce no
commander. A single vehicle wins only if its chassis/crew predicate permits it;
otherwise the closest nonvehicle to the centroid wins, with the first candidate
retained on an equal distance. Vehicles still contribute to that centroid.

The crew predicate follows **entity placer568**, using chassis configuration,
not weaponryDD8. This also corrects the corresponding actor-operability source
description in the preceding ownership pass. The already reviewed crew gate
includes blocking state, named crew slots, Disable flags and minimum workers.

The commander pointer is squadA8. SquadA0 is a separate **display representative**.
For the relevant human branch, Quant reads actor1390→Human::eBreed59C; its native
property binding names this `icon_priority`. Other representative selection uses
the type ordering `train_part`, `marine`, `airborne`, `cannon`, `car`,
`armored_car`, `light`, `medium`, `heavy`. These priorities are not the
commander-election policy.

Adding a member rejects null, retired and duplicate actors, rebinds brain100,
subscribes the squad's secondary Delivery receiver to mask7, appends the raw
actor pointer and marks membership changed98. The scene-mode2/brain39C bit27
gate is retained in the contract. Removing a commander snapshots DB4 bit17,
backs up eligible orders, dirties leadership and clears the shared target.
Member departure and ownership handling retain the distinctions documented in
[ownership](ownership-map-25492057.md); mask1 alone does not remove every member.

The registry supports tag, commander, user ID9C, numeric ID78 and vector-index
lookups. Most scans skip null rows. The player/user/select lookup92F4B0 assumes
rows are nonnull and examines the first member. Results are borrowed pointers.
An empty named squad survives pruning; an empty unnamed one does not. Global
Quant uses the initial registry count, compacts null rows and publishes
`Events::Scene::cmSC_Squads`, event1006, when dirty. The separate pruning helper
clears dirty without publishing that event.

## What squad Quant updates

`9309C0 / 7B8000` joins these policies:

- Reelect an invalid or dirty commander, restore an eligible backup sequence or
  an existing group goal, and carry over the saved selection state when its
  actor/player gates allow it.
- Accumulate eligible members' XYZ positions and actorB88 flags. Most flag bits
  are ORed; the nibble at bits35..38 takes the maximum value. The full set of
  producers of that actor field is not closed by this pass.
- Refresh the shared target from qualifying occupied weapon places with a
  one-second deadline. Explicit squad target assignment uses two seconds.
- Check commander/lookahead state every0.3 seconds. Without an explicit
  formation, movement beyond3L or a forced update moves the smoothed position
  0.8 of the way toward the near lookahead, recalculates followers and activates
  their following flags. Explicit-formation checks use0.5 seconds and its busy
  predicate. These intervals pass through the previously mapped integer-clock
  conversion and timer logic.
- Refresh a waypoint goal when membership or commander changes; otherwise test
  completion against waypoint position/radius and brain39C bit6. Execute the
  waypoint context once, then advance unless halted. The no-commander branch
  considers all members and has a separate empty-action-list/near-member case.
- Expire the shared target and clear membership-changed98.

The eligible-member centroid is distinct from the first12 candidates used for
commander election. It has separate selection, inactivity, physical-link/kind,
Operatable and competitive-game exceptions. The manifest scopes those branches
to this Quant rather than presenting one universal definition of “alive member.”

SceneA1B320/8A2FB0 calls global squad Quant in the `squads` profiling section,
before its particles section. This call site does not by itself establish all
outer worker and callback lifetime guarantees.

## Individual movement goals

commander exists, it receives a direct brain goal; otherwise each member receives
a translated formation position around the requested point. The latter uses
member-centroid offsets and optional automatic placement. Brain39C bit7 records
whether there is a current waypoint.

`902FB0 / 789520` is the direct-goal producer. It clears an existing root through
brain slot13, resets bits6/7/9/11/29, sets6/8/25, clears auxiliary140XYZ and copies
goalXY to130. It does not itself allocate a new leaf order.

Follower recalculation `933100 / 7BA6B0` writes a different coordinate pair,
brain138XY. It needs a commander, at least two members and a nonbusy formation.
It obtains actor radius through entity slot16. For an explicit formation it
temporarily removes the commander from the position records; otherwise it
derives a direction from the follower centroid toward the near lookahead and
uses `commanderAhead` when placing the commander-relative layout.

then enables all of them; this is not a save-and-restore of arbitrary previous
enable states. In scene mode1 it clamps destinations through the pather cost
probe `8AD910 / 732790`: sample1+floor(distance/16) equally spaced steps and stop
before cumulative cost reaches100000, retaining the last accepted point. The

## Automatic placement and explicit lines

The base `set/squads.set` resource declares the same competitive/cooperative
defaults: minimum3, maximum9, radius20 and commanderAhead−8, in the configured
distance units. The constructor selects the appropriate block. Parsed values
remain mutable. The resource hash and52 squad/iterator token bindings are checked
alongside the binary evidence.

Automatic placement operates on `{X,Y,radius}` records:

1. Minimum-separation passes compare **surface gaps**, subtracting both radii.
   Below the minimum, pair contributions push apart by half of
   `1.1*minimum − gap`; contributions are averaged into shared scratch storage.
2. The commander-centered stage performs four clamp/repulsion iterations. Points
   outside its radius are brought to0.9 of that radius before separation.
3. The main placer performs five iterations. Connectivity uses surface gap below
   the maximum. For multiple clusters, closest cross-cluster pairs pull their
   clusters toward0.9 of that maximum gap. A centroid/radius pass scales an
   oversized layout to0.95 of the requested radius, then separation runs again.

This is an iterative heuristic. The later separation pass may expand a layout
again; the radius operation is not proof of a final hard radius bound. Shared
scratch vectors also leave an outer scheduling requirement.

The line-formation vtable's **slot0 generates positions**; it is not a destructor.
It alternates −1,+1,−2,+2 perpendicular steps from the supplied origin, with no
center row, and generates at least its configured minimum count. Slot1 returns
half the spacing times(count+1).

Assembly resolves a misleading decompilation of drag-to-spacing:

`spacing = min(S / pow(M,p) * pow(drag,p), S)`

where `S=maxSeparation*L`, `M=maxDragDistance` and `p=dragSensitivity`. Native
initializers bind the named variables to defaults8,700 and0.5 respectively.
For positive finite inputs this is `S*min((drag/M)^p,1)`. Exceptional CRT math
paths and invalid-input handling are not silently equated with that simplification.

The anchored formation keeps a five-sample rolling progress state, an absolute
position flag9 and a latched busy flag8. It uses assigned **total distance**, not
mean distance, together with its span/origin gates and change in rolling progress.
Replacement transfers ownership of the formation pointer and frees the old ring
and formation allocation.

## Assigning a soldier to a formation position

`BF630 / AFFE0` constructs every actor/slot pair. Its ordered key is the truncated
unsigned squared XY distance; collisions increment the key until unique. Thus
tie resolution can also affect reported metrics. Endpoints and degree counts
are bytes, and counts above254 trigger a diagnostic.

For a single pair it directly assigns the position. Otherwise it repeatedly
removes the highest-cost remaining edge, then scans ascending edges for forced
assignments. An actor with one remaining option is forced when there are at least
as many slots as actors; a slot with one remaining actor is forced when there are
at least as many actors as slots. The signed surplus is adjusted when deletion
exhausts an unassigned surplus-side vertex. Assigning a pair copies XY and removes
all other edges incident to either endpoint.

The result contains the square roots of minimum/maximum assigned adjusted keys
and the sum of square-root costs. This is not a nearest-neighbor loop, and no
global optimum is claimed. The red-black container mechanics are bounded
dependencies; they do not introduce a further AI scoring policy. Empty/invalid
input preconditions and upstream mutable UI settings remain explicit leads.

## Order transfer is a filtered serialization operation

A primary-RTTI census finds79 eOrder-derived tables in each binary. For slot8:
75 use the base false implementation; MoveTask and Advance return true;
eComplexOrder and eAirstrike return true when any child does. This closes the
located primary dispatch set for this predicate, not every order implementation.

The generic clone serializes/recreates a registered order. A complex clone with
flags0 uses the full generic clone. With flags1 it walks children in order:
skip children whose slot7 is false, stop at the first slot7-true child with slot8
false, and serialize accepted children into the new complex sequence.

Slot7 normally checks native registration. **MoveTask overrides it** with a
dynamic cast of task40 from `Pather::Task::eGeneric` to `ePoint`. Nonpoint movement
tasks therefore do not survive this filtered copy even though MoveTask slot8 is
true. “Eligible descendant exists” and “the clone retains the entire sequence”
are different claims. Squad removal and commander backup use these precise rules.

## Waypoint iterator and remaining graph work

The1A0-byte iterator stores direction, a raw actor filter, a raw current waypoint,
halted and four60-byte tags: start, previous, current and next. Setting/advancing
the iterator resolves the current tag in the global waypoint map. Its parser
remaps a serialized ActorID before looking up the filter actor.

Forward choice excludes the immediate-back edge while remembering that it exists.
With a nonnull actor filter, an edge's actor-ID membership test can be **overwritten
by its tag test** when the tag is nonempty. Include/exclude78 then determines
acceptance. A null actor filter bypasses these constraints. Eligible32-bit weights
are summed; a nonzero sum consumes the selected-context RNG and uses high24 bits
modulo that sum, then selects the first cumulative weight exceeding the draw.
The modulo choice is not exactly unbiased. With no selectable result it uses the
remembered back edge or an empty tag. Parser guarantees on weights are still open.

Reverse selection recursively searches outgoing edges for the parent of the
current waypoint. The reviewed helper has no visited set or local null-lookup
guard; this is a graph/precondition lead, not evidence that authored cycles are
safe. The iterator can generate up to three XYZ points. Random-position mode uses
two RNG draws: radius uniform from0 toR and angle from−π toπ, with Z set to0.
That distribution is not uniform over the area of the disk.

Waypoint object/edge parsing, graph edits and destruction, actor/filter pointer
lifetime and the concrete action context are the next connected investigation.
The wider remaining work is tracked in
[static-frontier](static-frontier-25492057.md).

their decompilations completed. The verifier checks fingerprints, instruction
