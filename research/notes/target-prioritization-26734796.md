# Autonomous target prioritization · Steam 26734796

**Use seven MinHook function entries.** The shared ranker returns a public vector of borrowed subjects. **Scoring and stickiness.** A nonnegative native ammo rule admits an effective, available, in-range pair. Use the pair with the highest score, breaking equal scores by higher rule priority. The score is `0.40 × danger + 0.35 / (1 + d / proximity_scale) + 0.25 × alignment`, plus applicable bonuses. The scale is 35 × L for infantry and 80 × L for vehicles across all weapon pairs. Distance and range use the raw subject feet position (+0x28). Danger combines normalized observed AttackRate (0.50), a visible enemy's active weapon targeting self (0.30) and native threat flags (0.20). Alignment maps the normalized direction dot product to [0,1]. An effective visible squad hint gets +0.12. A human incumbent at +0x3B8 or on the active weapon gets +0.20. A matching live or cached vehicle row target gets +0.30 on a shell-firing main gun of at least 50 mm and +0.20 otherwise. Native order breaks equal subject scores. Infantry carried weapons share the current hand sight origin. The engine owns weapon switching and final AP/HE selection.

**LOF geometry.** L is the positive finite f32 at game RVA 0x149E750, with fallback 20.0. Use the clean muzzle when available. For a missing or dirty bone, raise owner+0x74 by the muzzle height below. Raise the observed target feet by the aim height only for the ray endpoint. Read enemy type (+0x30 bit 2) and then human stance ([enemy+0xDE0]+0x2C, i32) only after confirming current visibility (subject+0x10 bit 29). A missing human chassis uses standing height.

**LOF budget and contacts.** All entries share four ray slots per outer actor invocation. Zero or one unique candidate costs zero rays. Test up to the four highest-scored candidates using a finite origin and effective pair. Ranking and the MG selector share cached results by subject, entity, place, weaponry revision and both endpoints. Only ranking spends rays. The live query uses 0xA409C0(mask 0x86803, owner, −1), 0xA40A20 and 0xA40AC0, with 16 initial 0x48-byte hits allocated by 0x373650. Terrain and water block strictly before `max(0, length − 0.35 × L)`. Inspect blocking volumes through the full endpoint using `(vol[0x28] & 0x20) == 0 && (u32(vol+0x0C) & 2) != 0`. A first target contact clears the chord. A first foreign blocking volume, including a friendly, blocks it even inside the terrain tolerance. Release query scratch (+0x90/+0xA0, stride 8) and hits using final capacity and 0xDA1E38, recovering the aligned allocation at begin−8 for sizes ≥0x1000. The serial scope permits the native 0x7A8410 transform refresh. The engine resolves final aim and projectile arcs.

**When to reorder.** With any open effective candidate, place open candidates first by score, then the other effective candidates by score. Keep the ineffective or unseen tail in native order. With no open candidate, substitute the best visible effective candidate only if the stock head scored below zero. Otherwise retain the stock head and order, including when every candidate is out of range. For the picker shortcut and initial cover attempt, the stock head is the native return or argument. For the cover list it is the post-swap hint when present. For vehicles it includes the final preference prepend. This gives a rifleman a visible soldier over an ineffective tank or old contact even when the soldier is behind a hedge.

**MG coverage and shell economy.** Enable the mode-0 MG-first policy whenever assignment captures both a mounted MG (weapon tag `mgun`) and a shell-firing main gun (finite definition calibre +0x1628 ≥50 mm and a `shell` ammo record). This gate is independent of shortlist LOF. Scan the four committed sensor categories for a second currently visible enemy within the largest main-gun ammo+0x498 or effect slot-5 radius. For an isolated soldier, offer eligible MG rows first. Successful native selection records (subject, MG row) for this assignment. On a subsequent pass for that soldier, temporarily mask the main-gun rows. If the MG-only call fails, mask the MG rows already tried for the native fallback. With no eligible MG, call the ordinary selector directly. Each mask restores the original used bytes. Both passes use the same caller-owned result, and the engine owns the 0x7E35E0/0x7E1EC0 location operations.

**Vehicle approach and detour.** 0x9A7FB6 resets +0x3D4 to −1. For the first successfully selected pair, distance ≥ current weapon range takes 0x9A832A/34/41, stores **f32 range** at +0x3D4, clears the +0x3D8 deadline and consumes the row. An in-range cached row can reuse its eTarget when +1 is set and +0x30 matches subject+0x18. The scheduled resolver at 0x9A83F2/0x9A8558 may fail. On the due, empty first trial with no existing deadline, 0x9A85ED–0x9A8647 arms +0x3D8 for now + uniform(2,4) seconds. That failed trial can leave the row free. Charge wait/aim-only branches can consume a row. A later successful trial can clear +0x3D8. The autonomous root at 0x9AEDA0 takes the vector head, uses 0.95 × +0x3D4 for approach and tests +0x3D8 at 0x9AF4D3 for detour. Put the known-open #2 first **before assignment and root traversal**, so its eligible row gets first opportunity. The native trial decides whether it can fire. When all tested options are blocked, a visible effective stock head keeps its ordinary approach/detour trial. An ineffective stock head also stays first if there is no effective in-range alternative. Only the native assignment writes these timers or consumes a row beyond the temporary selector masks.

**Output and runtime boundary.** Infantry proceeds through 0x96B430's WeaponFire construction and native child dispatch. Vehicle assignment uses 0x81F0C0 mode 2, 0x81FCB0 copies the native target, then the host can emit eWeaponTargetCommand (ID 0x0C, 0xAB4E0 → sender slot 1 at 0x151340, receiver 0xAB640). The verifier checks image data and instruction sites. Live ABI, aim success and multiplayer agreement remain untested.

## Integration and review boundary

Include the header in the host translation unit. Pass the lowercase SHA-256 **measured from the loaded executable's on-disk file** to `goh::target_prio::install(g_Base, measured_sha256, MH_CreateHook, MH_RemoveHook, LogMsg)` after MinHook initialization and before the existing batch enable. Installation prepares seven disabled entries and rolls back its own successful creates on failure. Bracket the existing `origActorSlot23(actor)` with `enter_actor_scope(actor)` and `exit_actor_scope(actor)` on every normal or unwinding exit, independently of the grenade count. A nested invocation suspends the outer decision budget. Call `after_hooks_removed()` once callbacks have quiesced and the hooks have been removed. The header is standalone for review. The structural validation below covers native evidence, while the MinGW syntax check covers the C++ interfaces.

**Runtime diagnostics.** After integration the supplied `LogMsg` callback writes to the host's `grenade_dodge.log`. Promotions and successful MG-first selections have separate counters. Each logs events 1–25 and each multiple of 100, and resets on hook removal. A promotion records actor, role, hook stage, old and promoted subject, reason and the number of candidates with a blocked ray in that plan. Stages distinguish preliminary vehicle rank changes from final assignment. An MG-first event identifies the actor, subject and accepted row before the native firing trial.

## Reproducing the checks

From the repository root set `game_root` to the installed game directory. The method list reconstructs the focused TSV in the original export order.

```sh
map=research/artifacts/build-26734796/target-prioritization-26734796.json
exports=local-work/exports/build-26734796
tsv=local-work/target-prioritization/candidates.tsv
mkdir -p local-work/target-prioritization
jq -r '.methods[] | [.entry_rvas.game,.label] | @tsv' "$map" > "$tsv"
local-work/compat-venv/bin/python research/scripts/run_headless.py --build-id 26734796 export \
  --focused --program call_to_arms.exe --candidates "$tsv" \
  --output "$exports/call_to_arms-target-prioritization"
local-work/compat-venv/bin/python research/scripts/verify_fine_map.py --map "$map" \
  --binaries-dir "$game_root/binaries/x64" --exports-dir "$exports" \
  --resources-dir "$game_root/resource" --output "${map%.json}-validation.json"
```
