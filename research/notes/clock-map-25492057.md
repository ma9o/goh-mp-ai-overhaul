## Frame delta production

Main loop57B750 /404670 derives delta from QPC when fixed override154C158
/13B56C8 is zero.657E80 /4CD410 first establishes `counts_per_ms =
QueryPerformanceFrequency()/1000`.

For the reviewed ordinary finite-value path:

```text
seconds = float((qpc_difference * 1000) / counts_per_ms) * 1e-6
if fixed-cadence option:
    seconds = 0.04, or 1/configured_frequency when nonzero
raw_ms = trunc(seconds * 1000)
delta = clamp(trunc(float(raw_ms) / actual_slowdown), 1, 100)
```

The QPC difference is sampled at frame preparation relative to the previous
quant-cadence sample; it is not simply asserted to be the full wall duration of
every rendered frame. Integer truncation precedes slowdown division. A larger
factor reduces derived simulation delta. **A nonzero fixed override bypasses
this formula, division and clamp entirely.**65F380 /4D46D0 copies the supplied
integer unchanged. Override setter57B3B0 /4042D0 uses memory XCHG.

The main-loop event slice is Prepare16 → Start17 → RoEnd1A → delta setter →
RwStart1D → End20 → FinallyRender26 → FinallyQuant23 → UpdateStats29. Actual
slowdown can change in quant after the frame delta has already been selected.
Event-router and worker execution semantics still need tracing before treating
this sequence as a complete synchronous scheduling model.

Frame flags getter57B370 /404290 reads147B848 /12F33E8. Setter57B380 loads flags,
computes OR mask or AND~mask, then exchanges the result into memory and returns
the replaced value. The load/compute/exchange is **not a single atomic OR/AND
read-modify-write**. GEM4042A0..4042BD contains the same leaf assembly but is not a
function in the frozen Ghidra database. Its bytes and raw LLVM decode are recorded.

Render helper57B3C0 /4042E0 saves flags, sets8, publishes17/1A/1D/20 and restores
flags. It contains no direct clock advance. Effects of callbacks reached through
those events are outside this local statement.

## Slowdown request precedence and serialization

65EBC0 /4D4080 manages18-byte rows: float target0,step4,transition-divisor8 and
uintptr token10. PaddingC is not assigned a semantic field. Missing tokens append;
existing tokens update in place **without becoming the last row**. Only the last
row controls the active transition.

Updating the top row computes `(target-actual)/divisor` and publishes FEF
`cmSlowdownUpdate`. There is no local positive/zero/finite validation. The game
has an early guardC0B460 testing global15A4A80; GEM's B25FA0 always returns false.
The game's guard producers and higher-level policy remain open.

When unpaused, core compares actual with last target. If their absolute difference
exceeds1e-5, it adds the stored step **once per quant call**. For a finite
step>+1e-5 it takes `min(new,target)`; otherwise it takes `max(new,target)`.
Consequently a small positive step≤epsilon takes the max branch. On reaching
epsilon of target it emits FEF. These are the literal branch rules, not an assumed
general-purpose interpolation algorithm for exceptional float inputs.

Remove65ED10 /4D41D0 shifts a non-top row out without recalculation/event. Removing
top recomputes the new top via65FB20 /4D4E50 and emits FEF if a row remains.
Removing the last row leaves actual50 unchanged. Getter65EBA0 /4D4060 returns
the last requested target, or1 for an empty vector; it can differ from actual50.
65EB80 /4D4040 requests token=self,target1,divisor1 and does not clear other rows.

Text load/save65F610/65F8C0 (GEM4D4960/4D4BF0) bind:

- `scenequant`: raw integer48, through65E7F0/65E810.
- `speed`: save target of the self-token row, even when another token is on top;
  load requests the parsed target using self token and transition divisor20.

Those two fields do not serialize the full slowdown stack or current interpolated
factor. They are relevant to reconstructing saved AI deadlines faithfully.

## Duration and deadline codecs

The map records the individual helpers65E750..65EA60 and GEM counterparts.
Duration codecs include text float×unitfactor, inverse text float, raw binary
integer and text integer.65E830 /4D3CE0 constructs now+converted float directly
without a negative/inactive gate.

The relative deadline codecs instead use0 as inactive. Save writes float−1 for0;
otherwise it writes `float(signed32(deadline-now))*reciprocal`. Load nonnegative
float gives `now+trunc(value*unitfactor)`; negative gives0. Both object-first and
stream-first variants were reviewed. Stream-first text-save leaves at65EA20
..65EA58 /4D3ED0..4D3F08 are raw-code evidence in both binaries, not claimed
Ghidra entries.

An expired nonzero deadline can therefore serialize a negative remaining
duration, then reload as inactive0. Absolute deadline integers are not copied by
these relative codecs. This does not establish wrap-safe ordering at every
consumer; several consumers compare unsigned deadlines directly.
